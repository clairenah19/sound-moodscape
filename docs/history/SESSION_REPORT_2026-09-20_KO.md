## 4. 가장 중요한 발견 — Gangnam은 단조로 들리지 않습니다

`6bc9ded` 커밋에서 사용자의 실제 `sunoapi.org` 키로 **10곡을 실제로 생성**하고, `librosa`의
비트 추적과 Krumhansl-Schmuckler 조성 추정(학계 표준 방법)으로 실제 파형을 분석했습니다.

### 템포: 겉보기보다 훨씬 좋습니다

원본 평균 편차는 70.6%로 최악처럼 보였지만, 10곡 중 6곡에서 검출 템포가 요청값의 정확히 2배
또는 ½배였습니다. 이는 느리고 타악기가 적은 음악에서 자동 비트 추적이 흔히 일으키는 옥타브
오류입니다. **보정 후 평균 편차 12.3%, 중앙값 1.1%** — 템포 매핑은 사실상 잘 작동합니다.

### 조성: 여기가 진짜 문제입니다

**장조/단조 일치율 10곡 중 5곡, 50%.** 동전 던지기와 같습니다.

특히 중요한 것은 `clip09` 결과입니다. 개발 계획의 Priority 2가 던진 질문이
*"Gangnam이 실제로 단조로 들리는가?"* 였는데, 답이 나왔습니다:

| 항목 | 값 |
|---|---|
| 요청한 조성 | **minor (단조)** |
| 실제 검출된 조성 | **A# major (장조)** |
| 검출 신뢰도 | **0.921 (매우 높음)** |
| BPM 편차 | 0.2% (거의 완벽) |

신뢰도가 0.92로 높다는 점이 중요합니다. 검출기가 헷갈린 게 아니라, **실제로 장조로 들린다**는
뜻입니다. 템포는 거의 정확히 맞췄는데 조성은 정반대로 나왔습니다.

다만 공정하게 말하면, 불일치한 클립들의 평균 신뢰도는 0.742로 일치한 클립들(0.885)보다
낮습니다. 일부는 진짜로 조성이 모호한 곡일 수 있습니다. 하지만 Gangnam은 그 경우가 아닙니다.

**해석**: 프롬프트에 "minor key"를 적는 것만으로는 Suno가 단조로 만들어주지 않습니다.
Pleasantness를 조성에 연결한 것은 코드상으로는 작동하지만, **들리는 결과로는 절반만
전달됩니다.** 이것은 실패가 아니라 실제로 측정해서 얻은 진짜 결과입니다 — 과학 전람회에서는
오히려 이런 종류의 정직한 음성 결과가 강합니다.

## 5. 문서가 코드와 어긋난 부분 (미해결)

`docs/history/MERGE_REPORT_2026-09-13.md`가 "Priority 0"으로 지목했던 문제가 **아직 그대로 남아 있습니다.**

`audio.js`를 직접 확인한 결과, 소리를 내는 신시사이저 폴백은 **존재하지 않습니다.**
`createOscillator()`는 파일 전체에서 단 한 곳, 접근성 내비게이션 틱에만 쓰입니다.
`animateWaveformSynthetic()`은 이름과 달리 막대 높이를 무작위로 움직이는 **화면 효과일 뿐**,
오디오를 만들지 않습니다.

그런데 세 곳이 여전히 신시사이저 폴백이 있다고 주장합니다:

| 위치 | 문구 |
|---|---|
| `index.html:69` | "지도, 무드 점수, 실제 사진, **신스 사운드스케이프가 즉시 작동**" |
| `about.html:164-165` | "**(3) 내장 Web Audio 신스 폴백으로 플레이어가 절대 무음이 되지 않음**" |
| `audio/README.md:3` | "내장 신스 폴백 **대신** 재생되도록" |

`README.md`만 9/13에 정직하게 수정되었습니다 ("이 버전에는 작동하는 신스 폴백이 없습니다").
나머지 세 곳은 수정되지 않았습니다. **앱 첫 화면이 사용자에게 사실이 아닌 것을 약속하고
있습니다.** 이것이 지금 가장 빨리 고쳐야 할 항목입니다.

## 6. 테스트 상태

`python3 -m unittest discover -s research -p test_research.py`를 직접 실행했습니다.

**7개 중 5개 통과, 2개 오류.** 실패가 아니라 의존성 누락입니다:

- 통과: 날짜 범위, 결측 vs 0 구분, 로그 스케일링, ISO 환산, 중복/해시/세션 검증
- 오류: `test_clip_level_correlation`, `test_small_sample_remains_pending`
  → 둘 다 `ModuleNotFoundError: No module named 'scipy'`

`numpy` 2.5.1은 설치되어 있지만 `scipy`가 없습니다. 구현 보고서의 "7개 전부 통과"는
scipy가 설치된 환경 기준이므로 거짓은 아닙니다. 다만 **저장소에 파이썬 의존성 파일이 없어서**
(`requirements-audio-analysis.txt`는 오디오 분석용만 있음) 다른 환경에서 재현이 바로 되지
않습니다. 심사위원이 재현을 시도한다면 여기서 막힙니다.
